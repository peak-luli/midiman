# Meetings (peak-luli standard)

Owner: **Felix**. Anyone who creates a calendar event must follow this. Felix is accountable for the bar.

## Purpose

Ishay should be able to open the invite and **prepare** — not decode a title full of ticket ids.

## Required calendar fields

### Title
Human outcome + context, not only ids.  
Good: `MidiMan · coach-clarity E3 (I13–I15) with Miriam`  
Bad: `I13 I14 I15`

### Description (always)

1. **Background** — 2–4 sentences: why this meet exists, what decision or refinement we need.  
2. **Agenda** — numbered items. For each work item:  
   - **Id + name** (e.g. I13 step-transition)  
   - **One-liner** in plain language (what Ishay would notice in the app)  
   - **URL** if it has one (GitHub issue, PR, doc)  
   - Optional sequencing / dependency note  
3. **Prep** — what to skim or think about beforehand (PR links, play notes, docs).  
4. **Links** — docs, PRs, related epics as needed.

When Miriam or Noa request a meet, they supply background + agenda one-liners + URLs to Felix **before** the invite goes out — Felix does not invent eng/product content.

### Time
Timezone explicit (default **Asia/Jerusalem**). Duration honest.

## Who creates the invite

- Felix creates company / cross-role meets by default.  
- Miriam may request meets; Felix (or calendar owner) still ensures the description meets this bar.  
- Noa/Joseph request via Felix unless Felix delegates.

## After the meet

- Decisions → Issues / product docs (Miriam / Noa as relevant).  
- Process lessons → Joseph chronicle when meaningful.  
- Update this file if the meeting bar itself changes.
